UUID와 서비스 주소는 연결 식별자이며 API 키가 아닙니다. 다른 환경에서는 `AGENTSTREAM_BASE_URL`, `AGENTSTREAM_CHATBOT_ID`, `AGENTSTREAM_WORKSPACE_ID`를 지정합니다. 코드 기본값은 위 팀 배포와 같습니다. 교육 워크스페이스의 기존 챗봇 ID로 되돌리지 않습니다.

팀 챗봇은 공개로 설정하고 기존 팀 API 키에 이 챗봇의 `CHAT_INVOKE`만 매핑했습니다. 키 발급 워크스페이스와 챗봇 워크스페이스가 같아야 합니다. 새 환경의 권한 설정은 운영자가 확인해야 합니다. 공개 웹의 접근 설정과 AgentStream의 API 인증은 별개입니다.

## 지식 문서와 답변 범위

다음 세 문서의 팀 지식베이스 적재 및 실제 검색을 확인했습니다.

- `01_SLP_분석방법_정의서.docx`
- `SLP_data_dictionary_02_resaved.docx`
- `03_SLP_판정기준_관리표.docx`

교육 환경에서 적재에 성공한 원본을 사용하고, 팀 환경의 파싱 검토 본문을 v1.1로 보완했습니다. 필드 범위 표기, 팀 앱의 집계 정의, AIStream 적용 범위·보류 해석을 반영했습니다. 원천 생산 행이나 키는 지식 문서에 포함하지 않았습니다. 문서와 챗봇 설정은 외부 플랫폼의 상태이며 저장소를 복제하는 것만으로 생성되지 않습니다. 원본 문서와 비공개 프롬프트 전문은 이 저장소에 포함하지 않습니다.

RAG는 계산 의미와 근거를 검색합니다. 실제 관측 수치는 앱이 전달하는 계산 결과를 사용합니다. SQL·Plotly 에이전트는 연결하지 않았으므로 챗봇이 DB 직접 조회나 차트 생성 성공을 주장해서는 안 됩니다. AIStream 운전 패턴 분석은 별도 API이며 로컬 선형 미래 참고 예측과 구분합니다.

## API 계약

서버에서 `X-API-Key` 헤더로 호출합니다. 키를 브라우저에 제공하거나 로그인 Cookie·Authorization·사용자/조직 헤더로 대체하지 않습니다. 시스템 프롬프트는 플랫폼에 저장된 설정을 사용하며 앱이 매 질문에 복사하지 않습니다.

1. `GET /open/v1/chatbots/{chatbot_id}/health`: JSON `status=healthy` 확인. unhealthy/unknown은 보류합니다.
2. `POST /open/v1/chatbots/{chatbot_id}/sessions`: `{"query":"첫 질문"}`, HTTP 201의 최상위 `session_id` 확인.
3. `POST /open/v1/chat-sessions/{session_id}/messages`: `{"message":"질문"}`. 첫 질문도 이 API로 전송하고 후속 질문은 같은 세션을 사용합니다.

메시지 응답은 `application/x-ndjson`입니다. 실제 응답의 `event`는 `assistant.delta` 같은 이벤트명이고, `type`은 `AIMessageChunk` 같은 메시지 자료형일 수 있으므로 **event를 우선**합니다. JSON 줄·한글이 네트워크 청크 사이에서 분리되는 경우를 처리하고 중복 `event_id`는 제외합니다. assistant.delta의 문자열과 `type=text` 블록만 표시하며 추론·도구 내용은 답변에 붙이지 않습니다.

`turn.completed`와 비어 있지 않은 답변을 모두 확인해야 완료입니다. tool.failed·turn.failed·불완전 종료·타임아웃·취소 시 부분 답변과 기존 계산표를 유지합니다. 실패한 POST를 자동 재전송하지 않으며 완료 여부가 불확실한 대화는 새 대화로 진행합니다.

## 분석 문맥 전달

앱은 이미 계산한 여러 보고서를 설명용 문맥으로 전달합니다. 중첩된 `분석조건/표` JSON을 단일 입력 표로 보내면 실제 API가 `INVALID_TABLE_INPUT`으로 거부했던 이력이 있습니다. 여러 보고서를 하나의 행 배열로 변환하는 것만으로도 서로 다른 표의 빈 행과 계산값 의미가 혼동될 수 있어, 현재는 **표별 원래 행수와 행·항목·값을 명시한 문장 목록**으로 전달합니다. JSON 표로 오인될 수 있는 대괄호 제목과 JSON 코드 블록은 사용하지 않습니다.

문자열 식별자의 앞자리 0, 숫자 0·음수, true/false와 결측(null)을 구분합니다. 한 표가 비어 있어도 다른 표까지 비었다고 해석하지 않습니다. 전달할 표의 합계 2,000행, 기존 표별 행·열·셀 제한 및 질문을 포함한 UTF-8 1MiB 한도를 적용합니다. 한도 초과 시 데이터를 잘라 보내지 않습니다.

방문자·분석 범위별 대화를 분리하고 생성/질문 버튼을 눌렀을 때만 전송합니다. 자유서술 정비 메모·조치내용 원문과 재생의 미래 실측 비교는 입력에서 제외합니다. 입력·답변은 AgentStream의 보관 정책을 따릅니다.

## 검증과 한계

`test_agentstream.py`는 이벤트명/자료형 구분, 한글·JSON 분할, 중복·비텍스트 제외, 실패·취소·타임아웃, 대화 격리, 후속 세션 재사용, 다중 보고서 값 보존을 대역 API와 합성 데이터로 검증합니다. 전체 테스트 기록은 [제출 점검표](SUBMISSION_CHECK.md)를 참고하세요.

팀 배포의 실제 검증에서는 health, 가상 첫 질문·동일 세션 후속 질문의 완료, 실제 분석 자료의 도구 실행·답변 완료를 확인했습니다. 공용 LOT 화면에서도 첫 질문·후속 답변이 완료됐고 ZIP의 HTML·JSON에 마지막 실제 AI 답변이 보존됐습니다. 이는 실제 기업 데이터나 키를 저장소 테스트에 포함했다는 뜻이 아닙니다.

답변 정확성 전 항목이 통과한 것은 아닙니다. 복합 질문에서 규격 미제공을 미등록으로 단정하거나 문서의 절 번호·예측 조건을 부정확하게 표현한 사례가 남아 있습니다. 생성 완료는 사실·근거 검증 완료를 뜻하지 않습니다. 계산표·승인된 현장 기준과 대조하고, 보류를 정상·불량 확정이나 생산 진행 승인으로 사용하지 않습니다. 장시간 안정성과 부하 검증은 별도입니다.
