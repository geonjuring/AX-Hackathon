## 향후 예측 · 종합 주의사항 · 모의 알림

두 리포트 끝에 동일한 흐름을 추가했습니다: 향후 운전 추세 → 권장 조치 → 모의 알림 → 종합 주의사항.

- `slp/analysis/forecast.py`: 동일 호기·Grade·Color의 최근 60일 중 최대 30개 일별 중앙값으로 향후 3일 선형 추세를 계산합니다. 일별 60건 이상, 최소 7일을 요구하며 최근 기록이 7일보다 오래됐거나 관측 간격이 7일을 초과하면 보류합니다. LOT 종료 시각 / 설비 분석 마지막 MES 생산일 야간조 종료 시각 이후의 기록은 제외합니다.
- 예측은 같은 제품·조건이 지속된다는 가정입니다. 회귀 잔차 ±2배는 참고 범위이며 검증된 신뢰구간·고장확률·운영 임계값이 아닙니다. 사전 예측 정확도를 검증한 모델은 아니므로 재측정과 담당자 검토가 필요합니다.
- `slp/reporting/sections.py`: 기존 판정에 따라 다음 생산 전 점검·재검·기록 보완과 종합 주의사항을 제시합니다. 기존 판정 및 계산 수치는 변경하지 않습니다.
- `slp/ui/demo_alarm.py`: 가상 직원 A/B/C의 `원본_직급=미확인`을 유지하고 별도 `시연용_역할=담당자/반장/관리자`를 저장합니다. 실제 메시지를 전송하지 않습니다.
- 사용 순서: 시연 임계값 설정 → 예측 조건 평가(또는 가상 이벤트 발생) → 시연 시간 1분씩 진행 → 미확인 시 설정된 대기시간마다 상위 알림 → 확인 시 상위 알림 중단 → 조치 완료·해제. 같은 미해제 내용은 중복 생성하지 않으며 해제 후에는 재발생할 수 있습니다.
- 알림과 시연 시간은 리포트별 세션 상태에만 저장됩니다. 새 세션이나 서버 재시작 후 유지되는 운영 알람 시스템은 아닙니다.

검증: `python -m unittest discover -s tests -t . -p 'test_*.py'` (프로젝트 루트), 기존 숫자 대조 스크립트 2개. 화면은 Streamlit AppTest로 두 메뉴와 모의 알림 흐름을 확인합니다.


## 비교값 강조와 판정 보류

- `slp/common/table_display.py`는 화면 표시만 담당합니다. 하회는 파란색·굵게, 상회는 빨간색·굵게 표시합니다. 결측·기준 없음·동일 값은 색칠하지 않습니다.
- 물성은 MES 규격 하한·상한, 처방은 같은 LOT의 기준·설정값, 공정조건은 비교 LOT 중앙값의 평균, 설비 같은 Grade 운전값은 기준기간 중앙값과 비교합니다. 배럴 실측값은 기존 집계의 설정 ±10℃ 참고 범위 밖만 강조합니다.
- 비교 방향과 품질·설비 이상 판정은 구분합니다. 허용기준이 없는 항목의 화면 판정은 `판정 보류 · 기준 필요`이며 관측·비교 결과 및 필요한 기준을 함께 표시합니다. 임의의 허용오차를 추가하지 않습니다.
- MI·IZOD 중 미측정·규격 없음으로 확인할 수 없는 항목이 있으면 이탈이 확인되지 않아도 `데이터 부족`으로 처리합니다. 한 항목이라도 규격 이탈이면 `있음`을 유지합니다.


## 데이터 품질 · 과거 재생 · 다운로드 · 숫자 표시

- 두 메뉴의 기본 `이력 분석`에는 데이터 품질 요약을 추가했습니다. 기록 건수, 시각 누락, 동일 호기·시각 중복, 10분 이상 공백, 생산이 있으나 기록 360건 미만인 교대, 주요 운전값의 NULL·비유한 수치 누락을 보여줍니다. 0은 자동으로 누락 처리하지 않습니다. 짧은 생산과 제품 전환도 고려해야 하며 기록 비중을 수집 완전율로 해석하지 않습니다.
- 왼쪽 `분석 모드 → 과거 사례 재생`에서 기준 생산일을 선택하거나 하루씩 이동합니다. LOT는 선택 LOT의 호기·Grade·Color를 고정 조건으로, 설비는 마감 이전 마지막 가동 제품을 기준으로 사용합니다. 정상 이력 분석의 전체 기간 결과를 재생 입력으로 재사용하지 않습니다.
- MES 생산일 야간조 종료(다음 날 08:30 직전)를 마감시각으로 설정합니다. 과거 60일 동일 제품 센서값에 생산일·기록시각 제한을 함께 적용합니다. 품질 요약의 생산실적도 input_dt가 마감 이전인 기록만 사용합니다. 센서 입수 시각 및 제품정보 수정 이력이 없으므로 당시 시스템 상태 전체를 복원한 것은 아닙니다.
- `이후 실제 결과 공개`를 켰을 때만 뒤 3일 동일 제품의 실측값을 조회합니다. 마감 이전 예측은 그대로 유지하고 항목별 절대오차·평균절대오차와 참고범위 포함 여부를 표시합니다. 이후 실측이 없으면 0으로 대체하지 않습니다. 예측 보류 시 오차를 계산하지 않습니다.
- 재생 날짜별 모의 알림 상태는 분리됩니다. 실제 메시지는 발송하지 않습니다.
- 두 모드에서 HTML 리포트 및 전체 자료 ZIP을 다운로드할 수 있습니다. HTML은 인쇄/PDF 저장을 지원하는 독립 문서입니다. ZIP에는 HTML, JSON, UTF-8 BOM CSV가 들어갑니다. 분석조건·마감·모델버전·품질·예측·권장조치·주의사항·현재 세션 모의 알림 이력을 포함합니다. 미래 실측은 공개한 재생 리포트에만 포함됩니다.
- `slp/common/number_format.py`와 `table_display.pretty`는 계산값/정렬용 숫자를 유지하며 불필요한 소수점 끝자리 0만 제거합니다. 숫자 0·유효 소수·문자형 LOT 코드는 유지합니다. 결측은 `—`로 표시하고 JSON에서는 null로 보존합니다.

추가 검증: 미래 실측 변경 시 과거 예측 불변, 늦게 입력된 생산실적 제외, 미래 실측 없는 상태, HTML 이스케이프, ZIP/JSON 수치 보존과 숫자 포맷. 화면은 두 모드의 날짜 이동·실제 결과 공개·다운로드·모의 알림을 Streamlit AppTest로 검증합니다.


## 전체 호기 기본 조회

설비 화면의 기본 호기는 `전체 호기`입니다. 한 기간의 모든 호기에 대해 품질 요약, 효율, 정지, 불량 기록과 종합 주의사항을 비교하고 HTML/ZIP을 다운로드할 수 있습니다. 기록 없는 호기도 누락하지 않으며 가동률은 미확인으로 표시합니다. 전체 재생은 선택한 날짜까지의 집계이고 제품별 예측·모의 알림 상세는 개별 호기로 진입합니다. 일괄 정지 집계는 기존 개별 분석의 반올림과 판정 순서를 동일하게 적용합니다.

모듈 함수·인터페이스를 변경한 배포 후에는 기존 프로세스의 모듈 캐시가 남지 않도록 정상 재시작하고, 실행 중 서버의 화면 요청을 통해 검증합니다.


## AgentStream 연결

서버 환경변수 설정과 팀 챗봇 구성은 [AgentStream 연결 안내](AGENTSTREAM.md), 시작·재시작은 [배포 안내](DEPLOYMENT.md)를 참고합니다. 키가 없으면 규칙 기반 설명을 사용합니다. 팀 배포에서는 공개·CHAT_INVOKE 설정과 실제 첫 질문·후속 답변을 확인했으며 새 환경은 별도로 검증해야 합니다.

### 호출·응답 처리

1. `GET /open/v1/chatbots/{chatbot_id}/health`: JSON status가 healthy일 때 진행. unhealthy/unknown은 보류.
2. `POST /open/v1/chatbots/{chatbot_id}/sessions`: `{"query": ...}`, HTTP 201 최상위 session_id 확인.
3. `POST /open/v1/chat-sessions/{session_id}/messages`: `{"message": ...}`. 첫 질문도 이 API로 보냄.
4. `application/x-ndjson`을 UTF-8 증분 디코딩하고 JSON 줄별 파싱. 실제 응답의 `event`는 이벤트명이고 `type`은 AIMessageChunk 등 메시지 자료형일 수 있으므로 event를 우선합니다. data 객체/최상위 content 형식을 수용합니다.
5. assistant.delta의 문자열 및 type=text 블록만 표시. 추론·도구 블록은 답변에 붙이지 않음. event_id 중복 제외. turn.completed가 있고 답변 텍스트가 있어야 완료. tool.failed/turn.failed/잘못된 JSON/타임아웃/정상 완료 없는 종료는 실패.
6. 이미 수신한 부분 답변과 이전 대화는 UI에 보존하고 규칙 기반 설명을 별도 표시. 실패한 POST는 자동 재전송하지 않음. 완료 여부 불명확한 대화는 새 대화로만 진행.
7. HTML·리다이렉트 응답을 JSON으로 처리하지 않음. API 키는 X-API-Key 헤더만 사용. 로그인 쿠키·Authorization·사용자/조직 헤더를 대체하지 않음.

### 분석 범위·세션·보관

- LOT·개별 설비·전체 호기에 생성/후속 질문을 제공하고 과거 재생에서도 마감 이전 입력·참고 예측만 전달합니다. 공개한 미래 실측 비교는 모델 입력에서 제외합니다.
- 자유 서술 정비 메모·조치내용 원문은 제외합니다. 판정표의 정비 원문 예시도 제거합니다. 선택 범위 집계·기준시각·필터·단위·예측 보류 정보를 전달합니다. null은 0으로 바꾸지 않습니다.
- 표당 2,000행·30열, 전달할 표 합계 2,000행·전체 20,000셀, 셀 문자열 1,000자·컬럼명 100자·질문 포함 UTF-8 1MiB 제한을 검사하며 초과 시 자르지 않고 오류를 알립니다. 여러 계산표는 단일 JSON 입력 표가 아닌 표·행·항목을 구분한 설명 문맥으로 전달합니다.
- 서버가 만든 방문자 UUID + 워크스페이스·챗봇·분석 컨텍스트 + 자체 대화에 세션을 보관합니다. Streamlit session_state 단위 격리, 동일 대화의 동시 요청 차단. 방문자가 API session_id나 챗봇 ID를 입력할 수 없습니다. 비밀값·session_id를 화면/리포트에 출력하지 않습니다.
- 같은 분석 범위의 후속 질문은 같은 세션을 순차 사용하며, 새 리포트 생성·새 AI 대화·분석 범위 변경은 별도 대화입니다. 이전 컨텍스트는 현재 브라우저 세션 내 최대 10개 유지합니다. 서버 재시작 시 앱의 대화 상태는 사라지지만 **AgentStream 측 대화·입력·응답 보관은 별개**입니다.
- 생성된 답변의 출처 본문을 보존하고, 명시적 sources/citations 메타데이터가 있으면 제공된 문서명·요약 등만 보존합니다. 근거를 새로 만들지 않습니다. 차트·SQL 도구는 이번 챗봇에 연결되지 않아 이 클라이언트에서 추가 실행하지 않습니다.
- HTML/ZIP 내 설명은 생성 방식·완료 상태를 포함합니다. API 연결 상태만 확인한 것을 실제 모델 응답으로 표시하지 않습니다.

### 검증 범위

`python -m unittest discover -s tests -t . -p 'test_*.py'`로 호출 계약, 한글/JSON 분할 스트림, 중복/비텍스트 이벤트, 중간 실패·EOF·잘못된 JSON·취소·타임아웃, 권한 오류, 방문자 격리, 후속 세션 재사용, 입력 한도·결측 유지·원문 제외를 대역 검증합니다. 팀 배포의 실제 health·첫 질문·후속 질문 완료와 공용 웹·다운로드 검증은 [연동 안내](AGENTSTREAM.md)에 구분해 기록했습니다. 답변 정확성과 장기 안정성 검증 완료를 뜻하지 않습니다.

- 기본 서비스: `https://aiopen-serving.jntp-ax.or.kr/jntp-cpu/SV-32e32cdb`. 기존 실행 방식으로 앱을 열면 LOT·개별 설비·전체 호기·과거 재생 화면에 **AIStream 설비 운전 패턴 분석**이 표시됩니다.
- 선택 범위가 적용 조건에 맞으면 방문자 세션·분석 대상별로 한 번 실제 `/predict`를 호출합니다. 같은 화면의 질문·다운로드 등으로 다시 실행할 때는 저장한 결과를 사용하고, **AIStream 다시 분석**으로 명시적으로 갱신합니다. 실패도 세션에 보존하여 자동 재시도를 반복하지 않습니다.
- 모델은 `0.1.0-pilot`, **06호기 / SR-0310FMU / NP**, 모델 기준 확정일 **2026-10-01**에 한정됩니다. 전체 호기 화면도 이 조건만 평가하며 다른 호기를 정상으로 분류하지 않습니다. 범위 밖·기준 확정 전 기록은 보류 안내와 함께 분리합니다. 적용 예시는 LOT **64597658**, 또는 06호기·2026-10-28~2026-11-04입니다.
- 앱 DB의 선택된 LOT/생산일·호기와 실제 측정시각을 기준으로 입력을 읽습니다. LOT·호기별 제품 연결이 모호한 기록은 제외하며, 중복 plan 행으로 입력을 증식시키지 않습니다. 정지·센서 누락·중복 측정은 임의 제거하지 않고 모델의 보류 규칙에 전달합니다. 실제 0·음수는 보존하고 비유한 수치는 null로 전달합니다. 작업자명·정비 원문은 이 API에 보내지 않습니다.
- 최대 6,000행·900,000바이트를 기준으로 분할하되 같은 LOT의 10분 구간을 요청 사이에서 나누지 않습니다. 하나의 구간 자체가 너무 크면 보류합니다. 이 제한은 원격 API의 10,000행·2 MiB 한도 안에 여유를 둔 앱의 전송 상한입니다.
- 재생에서는 선택한 기준 생산일의 야간조 종료 시각 이후 기록을 쿼리에서 제외합니다. 이후 실측 공개 여부는 AIStream 입력에 영향을 주지 않습니다. 원본 입수·수정 시점의 완전한 복원은 아닙니다.
- 이상 후보·평가 보류·관련 운전값·전송 범위를 표시합니다. 시간 초과·429·503·잘못된 응답·분할 요청의 일부 실패는 기존 분석을 중단시키지 않으며 미응답을 정상으로 처리하지 않습니다.
- 기존 판정, 선형 참고 예측, 모의 알림을 유지합니다. AIStream은 관측 패턴 분석이며 미래 예측·고장확률·승인된 현장 판정이 아닙니다. 모의 알림 발생 기준에 이 점수를 자동으로 추가하지 않습니다.
- HTML/ZIP 다운로드에는 API 요약·구간별 결과·관련 지표·보류·오류와 원래 JSON 응답을 포함합니다. AgentStream을 나중에 설정하면 분석 요약과 최대 20개 후보를 설명용 문맥에 함께 전달합니다.

기본 주소는 코드에 설정되어 있으므로 키나 환경변수를 추가하지 않아도 현재 공개 서비스에 연결됩니다. 다른 배포를 연결할 때만 서버 실행 환경에서 `AISTREAM_BASE_URL`과 `AISTREAM_TIMEOUT_SECONDS`를 설정하세요. `.env.example`은 예시이며 앱이 자동으로 읽는 파일은 아닙니다. URL은 HTTPS 기본 경로, 제한시간은 3~120초(기본 45초)입니다. 모델·스키마·적용 범위가 바뀌면 클라이언트 계약도 함께 검토해야 합니다.

배포 서빙에서 Ray OOM이 발생했던 이력이 있습니다. CPU/GPU 표시가 아니라 실제 메모리 프로필과 재시작 로그를 확인하고 운영 자원을 설정합니다. 앱 연결은 메모리 감시를 끄거나 종료 임계값을 우회하지 않습니다.

검증: `python -m unittest tests.ai.test_aistream -v`는 범위 밖 호출 방지, 재생 마감·미래값 변경 격리, 제품 연결 모호성, 10분 구간 유지 분할, 0/음수/null, 분할 일부 실패, 프로토콜·HTTP 오류와 다운로드 수치 보존을 검증합니다. 실제 API·화면 검증은 별도로 진행하며 장시간 부하/서빙 최대 메모리는 별도 운영 검증 항목입니다.
